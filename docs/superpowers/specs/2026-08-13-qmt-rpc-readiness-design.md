# QMT RPC 就绪验证设计

## 目标

QMT 脚本默认允许 RPC 交易调用；设置页可对任意命名 QMT 实盘配置执行无副作用的
就绪验证，清楚区分 TCP、Token/协议、QMT 运行状态和行情能力。

## 服务端契约

- `RPC_ALLOW_TRADE = True`。
- 新增协议内置方法 `rpc.health`，不依赖 QMT 行情或交易 API，返回：服务名、
  协议版本、账号、账号类型、运行模式、交易权限和服务端时间。
- `rpc.health` 仍受 IP 白名单和 Token 校验保护。
- 验证流程不调用 `passorder`，不产生委托或撤单。

## 本地验证服务

新增 `sinan/live/qmt_rpc.py`，输入 `QmtRpcCfg` 后读取本机
`~/.qmt_rpc_token`，依次执行：

1. TCP 建连；
2. `rpc.health` 鉴权与协议验证；
3. `510300.SH` 名称与实时行情查询。

返回结构化结果；失败时标注 `tcp`、`auth`、`health` 或 `quote` 阶段，供 UI
直接展示。每一步使用独立连接，防止慢接口污染后续检查。

## 页面

“设置 → 实盘配置 → QMT 数据连接”增加“验证 RPC”按钮。点击后显示：

- 成功：连接地址、服务版本、账号、运行模式、交易权限、行情标的及最新价；
- 失败：失败阶段与可操作原因。

按钮验证当前表单中的 host/port/timeout，不要求先保存；Token 始终只从本机文件
读取，不进入 Streamlit 状态或页面。

## 验证

- 桥接测试锁定默认交易权限与 `rpc.health` 响应。
- 本地验证服务覆盖成功、TCP 失败、Token 失败和行情失败。
- UI 静态测试锁定按钮与结果字段。
- 浏览器验收页面交互后运行全量测试。
