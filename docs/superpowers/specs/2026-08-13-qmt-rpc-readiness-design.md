# QMT RPC 就绪验证设计

## 目标

在命名实盘配置中提供无交易副作用的 RPC 就绪验证，并将 QMT 单脚本的
`RPC_ALLOW_TRADE` 默认值改为 `True`。

## 协议

服务端保留一个协议内建方法 `__sinan_health__`。它不调用 QMT 行情或交易
函数，直接返回服务标识、协议版本、绑定账号、账号类型、模拟/实盘模式以及
`allow_trade`。该方法需要通过现有 Token 和 IP 白名单校验。

## 本地验证

验证器依次检查 TCP、健康协议、`510300.SH` 实时行情和绑定账户查询。每项
使用独立连接，避免一个 QMT API 超时污染后续检查。交易能力只读取健康协议
的 `allow_trade`，绝不通过提交测试委托验证。

## 界面

“设置 → 实盘配置 → QMT 数据连接”增加“验证 RPC”按钮。结果展示网络、
鉴权/协议、行情、账户和交易开关五项。网络、协议、行情、账户都成功时显示
“RPC 已准备就绪”；交易开关独立显示“已开启”或“只读”。验证使用当前表单
里的 host、port、timeout，即使尚未保存也可测试。

## 安全与测试

Token 继续只读 `~/.qmt_rpc_token`，不进入配置或日志。测试覆盖默认交易开关、
健康协议、真实本地 socket 验证器及页面按钮接线。验证器不调用任何交易函数。
